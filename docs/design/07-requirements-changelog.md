# 07 · 更新后的需求与变更日志

> 对应作业工件 4。基线 = 第一部分 SRS（含课堂反馈）。本节只记录**设计过程中被迫发生的需求变化**，
> 不重抄 SRS；变更一律给出"为什么"，并把结论回写成可验收的需求条目。
> 编号规则：`FR-*` 功能需求、`NFR-*` 非功能需求、`RR-*` 需求修订记录。

## 1. 变更总览

| # | 变更 | 类型 | 触发点 | 影响面 |
| --- | --- | --- | --- | --- |
| RR-01 | 新增**生成型练习卷**能力，且不计入掌握 | 新增功能 | 设计"单槽位出题"时发现：学习者无法主动做整卷练习 | 领域（独立表）、协议（`deep_question` 事件组）、UI（练习卷视图） |
| RR-02 | 题卡**事件权威化 + 历史回填 + 去重** | 细化功能 | 刷新页面会丢题卡 | 协议（`question_card`）、存储（消息 `data.card`）、UI |
| RR-03 | 知识库与主题**多对多**；题库按知识库分组 | 细化数据模型 | "接入文件夹资料"粒度过粗 | 领域（`sources` 派生归属）、API、UI |
| RR-04 | 回合**行为预算固定为常数**，结束原因显式化 | 细化非功能 | 只写"限制"无法验收 | 领域（预算常量）、Loop、前端（`turn_end.reason`） |
| RR-05 | "未判分"语义**扩展到题卷与刷题** | 一致性修订 | 只在单题上定义，多题场景会半途落库 | 服务、API（`ungraded_reasons`） |
| RR-06 | 新增**scratch 路径 / 会话绑定路径**；会话连续续接 | 新增功能 | 用户在未选主题时开口会无处可写 | 领域（`ownerSessionId`）、导航、UI |
| RR-07 | 导航 hand-off **只给卡片，不自动跳转** | 边界澄清 | 模型"开课"会绕过人的决定 | 工具契约、UI |
| RR-08 | 定性评估**精确化**：选择题可出但不授予掌握；`open` 判对降为部分正确 | 冲突裁决 | "概念题不算通过"与"允许给定性目标出选择题"冲突 | 判分、出题、门槛 |
| RR-09 | 设置中心**固定六个分组**；"测试连接"不做计费调用 | 细化功能 | 配置项散落会破坏可复现性 | 设置 API、探测、UI |
| RR-10 | 大纲质量**离线可评测**（F1 / 有界 / 无环 / 基线回归） | 新增非功能 | 生成质量无回归手段 | CLI、评测指标、CI 门 |

## 2. 修订条目（可直接验收）

### RR-01 生成型练习卷

| 字段 | 内容 |
| --- | --- |
| 需求 | 学习者可请求"生成一份 N 题（1–10）的练习卷"，按当前路径的知识点与目标生成，支持难度（easy/medium/hard/auto）与题型（choice/short/open）约束；逐题作答、整卷提交、提交后复盘。 |
| 明确不做 | 不占用"待答题单槽位"；不写掌握分数、不产掌握证据；不进入复习队列。 |
| 验收 | ①请求 N 题必须恰好生成 N 题，否则整卷失败；②提交前任何接口都不返回答案；③提交时若有题 `ungraded`，整卷零状态变更并返回原因；④重复提交幂等。 |
| 理由 | 单题回合适合"教学节拍"，但不适合"考前自测"；把练习与证据隔离，避免"刷卷刷出掌握"。 |

### RR-02 题卡权威化

| 字段 | 内容 |
| --- | --- |
| 需求 | 题卡以 `question_card` 事件下发，同时写入 assistant 消息 `data.card`；会话详情原样返回该投影；同一 `question_id` 在会话中只渲染一张待答卡。 |
| 验收 | ①事件与历史投影字段一致；②刷新页面后题卡仍在；③同一题重复出现时前端只保留一张。 |
| 理由 | 原设计只有"待答题槽位"，刷新或换设备即丢卡，学习者会以为"题没了"。 |

### RR-03 知识库多对多与题库分组

| 字段 | 内容 |
| --- | --- |
| 需求 | 一条路径可绑定多个知识库；一道题的"所属知识库"是**派生关系**（题目关联的知识点所属路径绑定了哪些库），可同时属于多个库；题库支持按库分组、按库 OR 过滤。 |
| 验收 | ①绑定新库不丢用户附加的文件来源；②同题在多个库视图下都可见；③解绑后题目不再出现在该库分组。 |
| 理由 | 主题常跨多个资料库（教材 + 笔记 + 规范）；把归属写死在题目上会产生"复制题目"的数据冗余。 |

### RR-04 行为预算与结束原因

| 字段 | 内容 |
| --- | --- |
| 需求 | 单回合工具调用 ≤ **6**；同一知识点连续出题（未作答）≤ **3**；同题提示 ≤ **2**；模型轮数 ≤ **6**。结束原因必须显式：`done` / `card` / `budget` / `max_rounds`。 |
| 验收 | ①第 7 次工具调用不执行且回合以 `budget` 结束；②连续第 4 次出题被拒绝；③前端可依据 `reason` 区分"正常结束"与"被预算截断"。 |
| 理由 | 不写常数就无法验收；不显式原因，前端无法解释"为什么导师突然不说话了"。 |

### RR-05 未判分扩展到题卷与刷题

| 字段 | 内容 |
| --- | --- |
| 需求 | 题卷提交、题库刷题与单题判分共用同一判分器；无法解析时返回 `ungraded` 并在题卷维度返回 `ungraded_reasons`，整卷不落库。 |
| 理由 | 同一套判分器若在两个入口语义不同，等于两套门槛。 |

### RR-06 scratch 路径与会话连续性

| 字段 | 内容 |
| --- | --- |
| 需求 | 会话可未绑定路径（scratch，`ownerSessionId` 标记）；`mastery_switch` 绑定到已有路径、`mastery_leave` 回到 scratch；进入学习页时若无 `session` 参数，自动接续该路径最近会话。 |
| 验收 | ①无目标时开口不报错；②scratch 且无知识点时不出现在主题列表；③删除会话时清理其 scratch 路径。 |
| 理由 | "必须先建主题才能说话"违反对话式产品的直觉；而写在全局又会产生脏路径。 |

### RR-07 导航只给卡片

| 字段 | 内容 |
| --- | --- |
| 需求 | 导师可"找到主题/会话"并生成 hand-off 卡片（含主题、模块、掌握数、到期数、可编辑开场语），但**不得自动跳转**；跳转由学习者点击触发。 |
| 理由 | 跳转是破坏当前上下文的动作；模型不能替用户做导航决定（自主级别 D）。 |

### RR-08 定性评估的精确边界

| 字段 | 内容 |
| --- | --- |
| 需求 | `concept/design` 的掌握只能由定性评估授予；允许为其出选择题（用于诊断），但选择题正确**不授予掌握**；`open` 题即使判对也只记 `partial`，不得单独授予掌握。 |
| 理由 | 这是 SRS 内部两句话的冲突点（"只做选择题不算通过" vs "可选题型含选择题"）。裁决原则：允许诊断，不允许通关。 |

### RR-09 设置分组与探测约束

| 字段 | 内容 |
| --- | --- |
| 需求 | 设置固定六个分组：`providers / llm / task-models / embedding / general / indexing`；"测试连接"只拉模型列表，不发起计费推理；模型维度探测仅在用户显式点击时执行。 |
| 理由 | 分组固定后，设置文件可被人工编辑且可向前兼容；"探测"若计费，会在用户不知情时产生费用。 |

### RR-10 大纲质量的可评测性

| 字段 | 内容 |
| --- | --- |
| 需求 | 提供离线评测入口，输出 `kp_precision / kp_recall / kp_f1 / count_in_bounds / acyclic`；默认门槛 F1 ≥ 0.8、相对基线退化 ≤ 0.05、KP 数在 [1,60]、前置图无环；不达标以非零退出码失败。 |
| 理由 | 生成型功能不能只靠"看起来合理"；要有可进 CI 的数字。 |

## 3. 非功能需求的更新

| # | 原表述 | 更新后 | 为什么 |
| --- | --- | --- | --- |
| NFR-01 | "判分不调用模型" | **判分、门槛、门控、复习调度、投影全部零模型调用**；可用离线测试证明 | 把口号变成可断言的边界 |
| NFR-02 | "首字节 ≤ 2s，整回合 ≤ 30s" | 保留；补充"单回合工具 ≤6、轮数 ≤6"的成本上界 | 延迟目标需要成本上界配合 |
| NFR-03 | "参考答案只存服务端" | 扩展为**三处投影白名单**（掌握题卡 / 题卷 / 题库刷题卡），并规定"提交后才释放答案" | 泄题面随功能增长，需要按出口治理 |
| NFR-04 | "服务默认仅监听本机" | 保留；**明确 `settings.json` 明文存 Key 为已知取舍**，并要求：Key 只进请求头、不回显上游响应、不写日志 | 诚实记录风险，而不是宣称"已加密" |
| NFR-05 | "状态与事件同事务" | 明确为"**同一 CAS 版本**：事件随新 revision 批量落库，失败整体回滚" | 让"同事务"可被审计（`revision` 对账） |
| NFR-06 | "领域层零模型依赖" | 扩展为"`domain` 零 I/O、零 Spring、`now` 显式传入"，并作为分层硬约束 | 保证判定可离线毫秒级断言 |
| NFR-07 | 无 | 新增"数据可移植"：删除 `data/` 中的对应文件即清空；`learning.db` 可独立备份/迁移 | 本地优先产品的隐性需求 |
| NFR-08 | 无 | 新增"错误可操作"：所有拒绝必须给出下一步动作（建议模式 / 需补充来源 / 需先作答） | 智能体系统的失败体验由拒绝文案决定 |

## 4. 冲突裁决记录

| 冲突 | 两种读法 | 裁决 | 理由 |
| --- | --- | --- | --- |
| 概念/设计能否出选择题 | A：不能（否则可糊弄）<br>B：能（诊断需要） | 能出，但**不授予掌握**；`open` 判对降 `partial` | 诊断价值保留，通关口子封死 |
| 谁能切模式 | A：只有学习者<br>B：导师也可以 | 双方都可以，但**必须写回服务端**并以 `session_meta` 告知 | 模型需要"建议进入复习"，但不能悄悄切 |
| 复习模式与到期 | A：只有到期项可复习<br>B：到期只是提醒 | B：到期影响排序，不影响准入；但**只能重测已掌握点** | 保持"到期=提醒"的产品语义，同时守住"复习不教新内容" |
| 重建大纲 vs 重新生成缺口 | A：重建一律需确认<br>B：缺口引导重新生成不需确认 | 重建需 `confirm`；"重新生成"只是重新调用导师，仍需走同一确认 | 两条路径都可能导致进度丢失，不能有一个后门 |
