# 01 · 设计摘要（约 500 词）

> 对应作业工件 1。中文正文约 1100 字（对应英文约 600 词的篇幅）。

## 我们做的是什么

MasteryPath 把一条学习目标组织成**可编辑的知识地图（大纲）**，并围绕它跑通「大纲 → 逐个知识点学习 → 检验 → 间隔复习」的闭环。第一部分给出的核心命题是：**教学决策交给大模型，能否推进交给确定性引擎**。第二部分的任务是把这句话变成可实施、可验证的架构。

设计把命题拆成三条硬边界，并让它们分别落在不同的层：

1. **判定边界**：判分、掌握门槛、模式门控、复习调度全部是 `domain` 层的纯函数，零 I/O、零网络、`now` 显式传入，因此可以离线单测、可以逐条复现；模型永远不参与"是否掌握"的裁决。
2. **协议边界**：一轮导师对话只走 WebSocket，其余操作走 REST；事件名、顺序与字段名是前端唯一依赖，因此被当作契约冻结（例如 `question_card` 必须剔除答案与关键词字段）。
3. **状态边界**：所有进度收敛到唯一聚合根 `LearningProgress`，写入必须经过"读版本 → 就地修改 → 版本比对写回"（CAS，重试 3 次），事件在同一事务内随版本落库；越界写入在编译期（分层依赖）和运行期（`mutate` 唯一入口）双重封死。

## 自第一部分以来的进展

- **架构视图成型**：C4 的上下文图 / 容器图 / 组件图、UML 部署图、7 个质量属性场景、15 条 ADR（见 [02](02-architecture.md)、[04](04-adr.md)）。逻辑架构固定为 `adapter → service → domain → storage` 的**单向依赖**，`domain` 不依赖 Spring。
- **智能体专项补齐**：第一部分只说明了"导师是一个 Agent Loop"，第二部分把它拆成五个可设计、可测试的关注点——角色（单导师 + 确定性引擎 + 任务模型）、工具接口（23 个工具、schema 手写、按模式静态归类）、记忆与状态（四层：聚合 / 消息 / 事件 / 题库与知识库）、编排（回合协议与预算）、护栏（投影剔除答案、调用期门控、未判分语义、破坏性动作需确认），见 [03](03-agentic-design.md)。
- **设计模型落地**：领域类图、出题-作答-判分的序列图、复习调度与模式切换的状态机、大纲生成活动图，见 [05](05-design-models.md)；界面信息架构与关键用户流程见 [06](06-ui-ux.md)。
- **风险显性化**：15 条架构风险与 12 个待 PoC 验证的未决问题被登记（[08](08-risks-open-questions.md)），而不是藏在"设计已完成"的叙述里。

## 需求改了什么，为什么

设计过程中暴露了第一部分的 4 处缺口，均已在 [07](07-requirements-changelog.md) 记录并回写为需求条目：

| # | 变更 | 触发原因 |
| --- | --- | --- |
| RR-01 | 新增**生成型练习卷**（`deep_question` 回合 + 独立题卷表），不写掌握分数 | 第一部分只有"导师出单题"，学习者无法主动做整卷练习；把练习卷与掌握证据**物理隔离**，避免绕过门槛 |
| RR-02 | 题卡**事件权威化 + 历史回填** | 原设计只有"待答题单槽位"，刷新页面会丢卡；改为 `question_card` 事件 + assistant 消息 `data.card` 双写，同 `question_id` 去重 |
| RR-03 | 路径与知识库改为**多对多**，题库可按知识库分组；新增"离开路径 → scratch 路径" | "接入文件夹资料"粒度太粗：一个主题可能同时用多个库，一次对话也不一定绑定某条路径 |
| RR-04 | 把行为预算、判分阈值、"未判分"扩展到题卷与刷题 | 第一部分只写了"提示参与降为部分正确"，未给常数；不落常数就无法验收 |

另有 3 处**冲突澄清**：①"概念/设计只做选择题不算通过"与"允许给定性目标出选择题"冲突，裁决为"选择题可出，但 `open` 题判对也只记 `partial`，不得单独授予掌握"；②"模式由学习者切换"与"导师可切换"冲突，裁决为"双方都可切换，但必须写回服务端并由 `session_meta` 告知前端"；③"复习模式只重测已掌握"与"到期是提醒不是许可"不矛盾，落为"到期只影响排序，不影响准入"。

## 当前状态

设计已落地为可运行系统：后端 8 张表、23 个工具、覆盖学习 / 会话 / 题库 / 知识库 / 设置的 REST 端点，前端 9 个页面路由（另有根路径重定向）与 305 个 i18n 键。仓库以 864 条自动化用例与 8 个 Gate 证据（G0–G7）作为"设计可实施"的凭据（`README.md` 阶段看板）。

尚未被验证的是**假设**，不是功能：模型质量对大纲与出题的影响、0.9 门槛与 0.90 模糊阈值的合理性、单进程上限、暗色主题与附件通道的缺口——它们进入第三部分的 PoC 清单。
