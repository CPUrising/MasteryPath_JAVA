# 10 · 带注释的参考文献

> 对应作业工件 8。共 9 篇，每篇注释 200–300 字，统一回答三个问题：**它说了什么 / 它改变了我们的哪个设计 / 它的局限在哪。**

## 引用如何影响设计（速览）

| 文献 | 直接影响的设计决策 |
| --- | --- |
| Brown 等《Make It Stick》 | 出题检验作为主环节、间隔与交错；"看懂了"的错觉 → 需要客观判定 |
| Karpicke & Roediger (2008) | 复习模式只重测、不重讲；检索本身即学习 |
| Wozniak & Gorzelanczyk (1994) | SM-2 间隔序列、EF 与失败重学（ADR-07） |
| Ye, Su & Cao (2022) | 作为**被否决的备选**：FSRS 需要日志拟合，冷启动不适用（ADR-07） |
| Brown, S.（C4） | 逻辑/部署/技术三视图与四级抽象（[02](02-architecture.md)） |
| Nygard (2011)（ADR） | 决策日志的格式与"记录被否决的方案"（[04](04-adr.md)） |
| Yao 等 (2023)（ReAct） | 回合内"推理-行动"交替、工具调用的编排与失败不毒化 |
| NIST AI RMF 1.0 (2023) | 护栏的分层（治理/映射/度量/管理）与"人在回路"的自主级别 |
| DeepTutor (HKUDS) | 模式门控、按类型门槛、题库同步等产品范式的起点 |

## 1. Brown, P. C., Roediger III, H. L., & McDaniel, M. A. (2014). *Make It Stick: The Science of Successful Learning*. Harvard University Press.

**说了什么。** 本书把认知科学的实证结论整理成四条可操作原则：检索练习（retrieval practice）、间隔（spacing）、交错（interleaving）与"合意困难"（desirable difficulties）。它反复强调一个反直觉现象：**反复阅读会制造"流利错觉"**——读者感觉越来越熟，但长期保持并没有提升；真正提升保持的是"被迫从记忆里取出"的动作。

**改变了我们的哪个设计。** 三条。第一，"检验"不是学完之后的附加环节，而是主环节——因此系统在 `study` 模式里把"讲解 → 出题 → 作答 → 判分"做成一个原子回合，而不是"先讲完一章再考试"。第二，复习模式（`review`）**只重测、不重讲**：重讲会重新制造流利错觉，而且在我们的架构里"复习推进前沿"会污染进度语义。第三，"感觉自己会了"必须与"系统认为会了"分开记录——这就是双轨进度（ADR-08）的直接来源：学习者声明只推进地图，不写分数。

**局限。** 本书面向人类教学设计，默认"题目质量由人保证"；在我们的系统里题目由模型生成，因此"检索练习有效"这一前提需要额外的题目质量护栏（结构校验、离线评测、坏题修复）。此外，书中对"间隔长度"只给原则不给公式，具体排期仍需算法（见 SM-2）。

## 2. Karpicke, J. D., & Roediger III, H. L. (2008). The Critical Importance of Retrieval for Learning. *Science*, 319(5865), 966–968.

**说了什么。** 实验对比"重复学习"与"重复检索"对长期保持的影响：在即时测验上两者相近，但一周后的保持率上，反复检索显著优于反复学习；更关键的是，**学习者对自己"学会了"的预测与实际保持率几乎不相关**——重复阅读组预测自己记得很好，实际最差。

**改变了我们的哪个设计。** 这篇文章是我们把"判定权"从学习者与模型手里拿走的主要依据。既然自我评估系统性偏乐观，"声明已掌握"就不能写分数（ADR-08），"模型觉得你会了"更不能作为门槛（ADR-01）。它同时解释了为什么我们坚持"到期复习自动重现"，而不是"等学习者想起来再复习"——人不会主动做对自己不利但有益的事。

**局限。** 实验使用的是外语词汇配对，迁移到"概念/设计"这类需要解释与迁移的任务时需要谨慎；这也是我们把 `concept/design` 单独划为定性评估、而不是套用同一正确率门槛的原因之一。另外，检索练习的收益依赖"题目覆盖目标"，题目与知识点的对齐质量由我们的"题库—知识点自动关联"承担，而这部分无法由本文提供方法。

## 3. Wozniak, P. A., & Gorzelanczyk, E. J. (1994). Optimization of repetition schedules in SuperMemo. *Acta Neurobiologiae Experimentalis*, 54(1), 59–62.

**说了什么。** 这篇短文给出了 SM-2 算法：以"易度因子"（EF）刻画材料难度，复习质量（0–5）决定 EF 的增减；间隔按 `I(1)=1 天`、`I(2)=6 天`、`I(n)=I(n-1)×EF` 递推，失败则回到短间隔重新学习。

**改变了我们的哪个设计。** 它是 ADR-07 的直接来源：我们采用与之一致的 EF 初值 2.5、下限 1.3、间隔序列与失败重学（回到 10 分钟），并把"质量"映射为我们的判分结论（无提示正确=5、有提示正确=4、部分正确=3、其余=0）。更重要的是它给了我们一个"可手算、可解释"的基线：产品早期没有足够数据训练参数时，**可解释的次优解优于不可解释的最优解**。

**局限。** SM-2 的 EF 是启发式，不建模"记忆稳定度"与"可提取性"的分离；它对"部分正确"的处理也较粗糙。我们在实现中保留了三件锚点（`nextReviewAt` / `lastReviewAt` / `scheduledAfterFailure`）以便将来切换算法，但明确不引入第二套间隔逻辑——**两套逻辑并存必然漂移**，这是我们在设计评审中否决"SM-2 + FSRS 混用"的核心理由。

## 4. Ye, J., Su, J., & Cao, Y. (2022). A Stochastic Shortest Path Algorithm for Optimizing Spaced Repetition Scheduling. *Proceedings of the 28th ACM SIGKDD Conference (KDD '22)*.

**说了什么。** 论文提出把间隔重复建模为"随机最短路径"问题，用记忆状态（难度 D、稳定度 S、可提取性 R）刻画遗忘，并通过大规模复习日志学习参数，得到比启发式更优的排期策略——这是 FSRS 系列算法的学术基础。

**改变了我们的哪个设计。** 它影响的是一个**被否决的方案**，而否决理由同样重要：FSRS 的优势建立在"大量真实复习日志"之上，我们的产品在冷启动时没有这些日志；强行套用默认参数，得到的只是"看起来更科学"的排期，且会把 `difficulty / stability / retrievability` 三个字段变成事实上的隐藏真相源。因此我们保留这三个字段的位置（便于将来迁移），但判定与排期只用 SM-2 的单一逻辑（ADR-07 / R-12）。这条取舍写进 ADR，避免后来者误以为"字段存在即已支持"。

**局限。** 论文的评估以语言学习类记忆材料为主，对"程序性/设计类"知识点的迁移效度未知；另外它需要稳定的复习行为数据，而自学者恰恰最不稳定。这两点让我们把"是否迁 FSRS"降级为后续迭代的开放问题（见 OQ-11 与 R-08），而不是本期承诺。

## 5. Brown, S. (2018–2024). *The C4 model for visualising software architecture*（c4model.com；亦见 *Software Architecture for Developers* 系列）.

**说了什么。** C4 用四个由粗到细的抽象（Context / Container / Component / Code）与一套与符号无关的约定，解决"架构图各画各的"问题：同一系统可以有不同层次的图，但每张图只回答一个层次的问题，并且必须写清"谁在用、边界在哪、依赖什么"。

**改变了我们的哪个设计。** 本文档的结构直接照此组织：L1 只画学习者、系统、模型提供方与资料文件夹（回答"系统为谁服务、依赖谁"）；L2 把系统拆成前端、后端、四个数据落点与外部服务（回答"运行时有哪些容器"）；L3 画后端分层（回答"代码里谁依赖谁"）。更重要的是它给了我们一条自我约束：**每张图只回答一个问题**——因此我们把"智能体回合状态机""类图""ER 图"分开放，而不是塞进一张"大图"。这与"设计质量比文档数量重要"的要求一致。

**局限。** C4 对"数据模型"和"行为（时序）"覆盖较弱，必须配合 UML（类图/序列图/状态机）使用；另外 C4 不提供"如何做决策"的方法，需要 ADR 补齐。我们在 [05](05-design-models.md) 中混用 C4 与 UML，并在图注中说明各自回答的问题，避免读者把"容器图"误当"部署图"。

## 6. Nygard, M. T. (2011). *Documenting Architecture Decisions*（ADR 实践的奠基性文章；亦收录于后续架构决策相关文集）.

**说了什么。** 文章主张用短小、不可变的记录保存"一个决策"：背景（Context）、决策（Decision）、后果（Consequences）。它反对把所有理由埋在长篇设计文档里，因为那样"改一个决定要重写全文"，最终无人维护。

**改变了我们的哪个设计。** [04](04-adr.md) 的格式与"一决策一记录"的粒度来自这里。我们在其基础上加了两列：**优先级**（★ 表示"改了就伤筋动骨"）与**被否决的备选**。后者的价值在实践中被反复验证：答辩与评审中 80% 的问题都是"为什么不那样做"，如果 ADR 里没有备选与否决理由，讨论就会退化为"再想一遍"。此外，"后果"一栏强制我们写下负面后果（写放大、单机上限、无断线续传），这些负面后果后来直接变成了风险登记册的条目。

**局限。** ADR 假设决策是"一次性、可冻结"的；本项目的阈值与生成策略显然还会变（OQ-11）。我们的处理是：**结构性决策用 ADR 冻结，参数性决策用常量 + 开放问题管理**。另外 ADR 不解决"决策之间的冲突"，需要额外的冲突裁决记录（见 [07](07-requirements-changelog.md) §4）。

## 7. Yao, S., Zhao, J., Yu, D., Du, N., Shafran, I., Narasimhan, K., & Cao, Y. (2023). ReAct: Synergizing Reasoning and Acting in Language Models. *ICLR 2023*.

**说了什么。** ReAct 让模型在"推理轨迹"与"行动（调用工具/环境）"之间交替：先想一步、做一个动作、读回结果、再想下一步。相比纯推理或纯行动，它在需要外部信息的任务上更少凭空编造，且行为更可解释——因为每一步行动都留下了痕迹。

**改变了我们的哪个设计。** 我们的 Agent Loop 就是这一范式的工程化：每轮"模型输出 → 解析 `tool_calls` → 执行 → 把结果写回历史 → 再推理"，并把每次调用作为 `tool_call` / `tool_result` 事件暴露给前端（[03](03-agentic-design.md) §5）。它还影响了两个细节：①**工具失败不毒化回合**（返回 `ok=false` 后模型可自行纠正），因为 ReAct 的价值恰恰在于"读到错误再调整"；②**状态快照前置**，把"下一步该做什么"作为事实提供，减少模型无谓的行动轮数。

**局限。** ReAct 假设"工具是可靠的、错误是可读的"，但真实系统中错误信息可能误导模型（例如越权拒绝会让模型反复换工具）。因此我们加了硬预算（≤6 次工具、≤6 轮），并在错误文案里总是给出"正确模式"这类可操作提示。另外 ReAct 不解决"何时停"的问题——结束条件（`done/card/budget/max_rounds`）是我们自己的设计。

---

## 8. National Institute of Standards and Technology (2023). *Artificial Intelligence Risk Management Framework (AI RMF 1.0)*. NIST AI 100-1.

**说了什么。** AI RMF 提出四个贯穿生命周期的功能：**Govern（治理）、Map（映射）、Measure（度量）、Manage（管理）**，强调风险管理不是上线前的一次审查，而是与系统设计并行的持续活动；并特别指出"人在回路"（human-in-the-loop）应依据风险等级配置，而不是一刀切。

**改变了我们的哪个设计。** 它让我们把"护栏"从零散的功能点整理成分层结构（[03](03-agentic-design.md) §6）：上下文隔离（Map 的边界）、工具契约与预算（Manage 的约束）、确定性裁决（Measure 的可验证性）、投影白名单（治理中的最小暴露），以及"人机确认"清单（重建、缺口、导航、声明掌握）。它还支持了我们"自主性分级 A/B/C/D"的写法：越不可逆的动作，越要人确认——这正是"按风险配置人的介入"的具体化。

**局限。** NIST 框架面向组织级治理，缺少"单机单用户小产品"的落地细则；对生成质量的度量也只给原则。因此我们把它的"Measure"具体化为可执行的东西：离线评测指标（F1/有界/无环）、判分一致率、投影契约测试。这些是框架给不了、必须自己设计的部分。

---

## 9. HKUDS. *DeepTutor*（开源项目，GitHub）.

**说了什么。** DeepTutor 把"掌握式学习"做成智能体能力：多模式工作区、按知识点类型的掌握门槛、间隔复习、题库同步、来源与缺口等。它证明了"用工具把教学与判定分开"在工程上可行，也暴露了一个产品问题：通用聊天、阅读、伙伴等能力会把学习闭环稀释。

**改变了我们的哪个设计。** 三点。第一，**范围收敛**：我们保留"模式—工具—门槛"骨架，砍掉通用能力，把"以地图为中心"作为唯一主线。第二，**模式门控下沉到调用期**而不是 UI 禁用——这是从"能力挂载"实践中得到的直接经验。第三，**题库与证据分离**：题库是回看与练习的场所，掌握证据是判定的输入，两者不共用一张表，避免"刷题刷出掌握"（ADR-15 的同类思路）。

**局限。** 作为开源项目，它的默认假设是"有可用模型 + 有资料"；我们的设计必须能在"无模型"时仍然跑通判定链路，因此多了"确定性回退"与"离线评测"这两块它不需要的东西。它也没有回答"单机无鉴权如何保证隐私"，这恰是我们把它列为高风险（R-06）而不是照搬的原因。
